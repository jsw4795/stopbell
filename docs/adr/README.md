# 아키텍처 결정 기록(ADR)

이 디렉터리는 StopBell의 아키텍처 또는 엔지니어링 방향에 실질적인 영향을 주는 결정을 기록한다.

## 목적

목적은 관료적인 절차가 아니다. 나중의 변경 사항을 원래 제약 조건에 비추어 평가할 수 있도록, 어떤 선택을 **왜** 했는지 보존하는 것이 목적이다.

## 이름 규칙

```text
ADR-001-short-title.md
ADR-002-short-title.md
...
```

## 템플릿

```markdown
# ADR-XXX: 제목

- 상태: 제안됨 | 채택됨 | 대체됨 | 거절됨
- 날짜: YYYY-MM-DD

## 배경

어떤 문제 또는 결정에 검토가 필요한가?

## 검토한 선택지

### 선택지 A

장점 / 단점.

### 선택지 B

장점 / 단점.

## 결정

무엇을 선택했는가?

## 근거

왜 선택했는가?

## 결과

무엇이 쉬워지고, 어려워지며, 제약되는가?

## 재검토 시점

어떤 미래 조건이 이 결정을 재검토할 근거가 되는가?
```

## 규칙

사소한 구현 세부 사항에 대해서는 ADR을 작성하지 않는다. 미래의 개발자가 합리적으로 의문을 제기할 수 있는 다음과 같은 선택에 사용한다.

- 폴링 모델
- 인증 전략
- 배포 플랫폼
- 알림 전달 모델
- 캐싱 전략
- 외부 교통 메타데이터의 영속화
- Persistence Strategy
